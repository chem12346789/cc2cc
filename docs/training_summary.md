# Training log summary

## How to update this file

- Re-scan every top-level regular `log/train-*.log`; do not traverse `log/trash/`.
- Exclude a log from the summary if its final recorded epoch is below 2000; if no epoch was recorded, report that as unknown rather than assuming it is below the cutoff.
- Preserve original line numbers. For training logs, filter output with `rg -iv 'warning|key|Loading|Adjusted' <log> | sed '/^$/d'` and note that excluded lines were not analyzed.
- Keep one row per log in each focused table (run settings, loss settings, effective weighting, and outcomes), with workspace-relative source links. Record `loss_type`, `normal_type`, each `loss_multiplier*`, enabled loss terms, `if_relative_weight*` switches, `append_mol0`, and `mol0_weighting`. Energy loss is always included; derive E/Abs/At/G in that order from the loss construction and logged `if_abs`, `if_atomic`, and `if_grad` values. For single-atom handling, treat `append_mol0` as extra copies beyond the original entry and report `1 + append_mol0` total occurrences per single-atom system; include `mol0_weighting` separately as its per-sample data weight. Do not equate relative-weight flags with effective weighting: inspect the logged `Adjusted scale` coefficients for the relevant components, summarize nonzero/zero counts and ranges, and note data-dependent disabling. These coefficients are printed before multiplication by `data_weight` and match the broad `Adjusted` filter, so inspect their numbers separately and report only summaries with workspace-relative source line links. Compare against the configured multipliers: a constant energy scale of 1 with multiplier 1 does not demonstrate energy-relative weighting. Document discrepancies between flags and scales rather than copying the flags into the effective-weighting field. Include distinct runtime terminations and numerical diagnostics separately; distinguish missing completion markers from explicit failures.
- Use descriptive link labels such as `[input](../log/train-1232817.log#L12)` instead of nesting a filename reference after the word input; keep standalone evidence labels short (for example, `L1027`).
- Verify every cited log line exists and the table covers all matching logs. Use relative Markdown links such as `[L1027](../log/train-4113237.log#L1027)`, not absolute server paths. In VS Code, Ctrl+click a link in the Markdown source or click it in the preview to open the workspace file at that line.


Scanned all 10 top-level regular `log/train-*.log` files via the workspace `log/` symlink; `log/trash/` was not traversed. No log with a final recorded epoch below 2000 is included. ## Shared settings

Runs generally use `transformer+dense_mix_e3nn_4_correct`, `gmtkn-def2`, `def2-QZVPPD`, AdamW (`lr=3e-4`, weight decay `1e-12`), cosine warm restarts (`T=160`, multiplier 2, minimum LR `1e-8`), float64, and target `tol_delta_grids`; the top-level logs use a configured limit of 12,500 epochs, while the saved `2751839` and `2725898` runs use 2,400 epochs. Evaluation is every 5 epochs. All logs use `MSELoss` with `L1Loss` normalization and multipliers `energy/absolute/atomic/gradient = 1/0.01/1/1`; energy, absolute, and atomic terms are enabled, while gradient is disabled in two top-level runs. Both saved runs enable the gradient term. Effective relative weighting is checked from the logged scale numbers for every run, not inferred from startup flags: eleven runs show E and At weighting, while [train-823200.log](../log/train-823200.log) shows At only (all energy scales remain 1). Some older runs report the atomic flag as false despite nonconstant atomic scales. The effective-weighting table gives measured nonzero scale ranges and counts, combining train and evaluation initialization records; zero atomic scales remain excluded from its nonzero range. See the [model setting](../log/train-1232817.log#L3), [optimizer and schedule](../log/train-1232817.log#L9), and [training arguments](../log/train-1232817.log#L19).

## Single-atom augmentation and weighting

`--append_mol0 N` adds N additional references to each one-atom dataset entry; including its original reference, each such system appears `N + 1` times. The same setting is used when constructing both train and evaluation datasets. `--mol0_weighting W` assigns each one-atom sample data weight W (multi-atom samples use their atom count); this weight is applied to the configured per-sample loss scales. Thus append count controls repetition, while weighting controls the contribution per occurrence. See [`BasicDataset`](../cc2cc/utils/DataBase.py#L28) and [per-sample data weighting](../cc2cc/utils/DataBase.py#L373).

The required filtered scan excludes lines matching `warning|key|Loading|Adjusted` (7,845 line matches across these logs). Thus “no diagnostics” below means no matches in the remaining filtered text; excluded warning lines were not analyzed. `Adjusted scale` numbers were inspected separately for the weighting summaries. No explicit convergence-success or non-convergence messages, nor explicit successful-run completion markers, were observed. Initial `Best ...: inf ->` values are loss-tracker initialization, not non-finite training failures.
